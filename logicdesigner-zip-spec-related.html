IM-LogicDesigner ZIP仕様 - 関連機能編

更新日: 2026-08-11

本書は、フロー定義編（logicdesigner-zip-spec-flow.html）・ユーザ定義編（logicdesigner-zip-spec-userdef.html）・ルーティング定義編（logicdesigner-zip-spec-route.html）のいずれにも収まらない、関連機能・連携先製品の情報をまとめる。IM-Copilot（RAGアシスタント）のサンプルフローを含むリソース一式の解析から、IM-Copilot関連の標準要素、アシスタント登録用データ形式、およびフローのスケジュール実行トリガの仕組みが確認できた。

1. 概要

解析対象としたのは、「サンプルRAGアシスタント」を構築するためのリソース一式（ガイド資料に添付されたと見られるアーカイブ）で、次の4つを含んでいた。

  • im_logicdesigner-data.zip — フロー定義ZIP（フロー定義編の形式）。「アシスタント応答」を行うフロー1件と、ベクトルストアを構築するフロー1件を含む
  • assistant_definition.json — IM-Copilotの「アシスタント」を登録するためのデータ（本章3節）
  • job-scheduler.xml — IM-JobScheduler（別製品）のジョブ・ジョブネット定義。ベクトルストア構築フローを定期実行するためのスケジュール設定（本章4節）
  • im_bloommaker-data.zip — IM-BloomMaker（別製品、ローコード画面作成ツール）のデータ。本書の対象外のため扱わない

この4点セットは、intra-mart公式のインポート・エクスポート機能が出力する単一のZIP形式とは異なり、複数の異なる形式のファイル・ZIPを束ねた「ガイド用リソース一式」と見られる。個々のファイル形式（assistant_definition.json・job-scheduler.xml）自体は、それぞれIM-Copilot・IM-JobScheduler側の実データ形式であると考えられるが、この束ね方自体が製品の標準エクスポート機能によるものかは未確認である。

2. IM-Copilot関連の標準要素

本サンプルには、フロー定義編10.3節の標準要素一覧（key.type: "application"）にない、新たな12種類のkey.idが含まれている。ほとんどはLLM連携・ベクトルDB操作など、IM-Copilotの構成要素として使われるものだが、im_errorEnd・im_sleepのように汎用的な制御・ユーティリティ要素も含まれる。

key.id分類properties役割
im_chatLLM連携continueOnErrorチャット補完（LLMへの問い合わせ）を実行する。入力はmessages（role/contentを持つメッセージの配列。contents配列を使えばテキスト・画像を組み合わせたマルチモーダルメッセージも表現できる）とoption（model・maxTokens・stops・streaming・temprature【原文ママ、スペルミスと見られる】・topP）
im_embeddingLLM連携continueOnErrorテキストをベクトル埋め込みに変換する。入力input、出力embeddings
im_vectorDbSimilaritySearchベクトルDBcontinueOnErrorベクトル類似度検索。入力embeddings（ベクトル）・category（検索対象カテゴリ）
im_vectorDbKeywordSearchベクトルDBcontinueOnErrorキーワード検索。入力category・keywords（配列）
im_reciprocalRankFusionベクトルDBcontinueOnError複数の検索結果をReciprocal Rank Fusion（RRF）で統合する。入力contentsList
im_addVectorDbContentsベクトルDBcontinueOnErrorベクトルDBへコンテンツを登録する。入力category・contents
im_removeVectorDbContentsベクトルDBcontinueOnErrorベクトルDBからコンテンツを削除する。入力category
im_splitTextテキスト処理chunkingMethodType（プルダウン。確認できた選択肢: RECURSIVE_CHUNKING）、continueOnErrorテキストをチャンクに分割する。入力text
im_extractTextテキスト処理continueOnErrorファイルからテキストを抽出する。入力fileSize・fileName・fileData
im_copilotGetAssistantMessageHistoryIM-CopilotcontinueOnErrorアシスタントのメッセージ履歴を取得する。入力threadId
im_errorEnd制御errorMessage（必須、EL式可）エラーとしてフローを終了する。im_endと異なりmappingRulesは使わず、properties.errorMessageに直接メッセージ（またはEL式）を指定する。確認例: "${$const.ERROR_MESSAGE}"
im_sleepユーティリティinterrupt（プルダウン: ERROR/CONTINUE）、waitTime（ミリ秒）指定時間処理を停止する

これらの要素も、フロー定義編10.1節で説明した共通の外形（executeId・key・label・properties・mappingDefinition）に従う。im_errorEnd・im_sleepを除き、いずれもcontinueOnErrorを持つ点は他の標準タスクと共通している。

localUserDefinition要素のpropertiesについて、フロー定義編10.5節ではdefinitionのみを持つ例を示したが、本サンプルではproperties: { "definition": {...}, "continueOnError": false }のように、definitionと並んでcontinueOnErrorを直接持つ例が見られた。localUserDefinition要素も、参照する定義の種類によってはcontinueOnError相当の設定を要素自身のpropertiesに持ちうる。

3. assistant_definition.json（IM-Copilotアシスタント登録）

IM-Copilotの「アシスタント」（チャット形式のUIから呼び出せる、あらかじめ定義された処理）を登録するためのデータ。二重JSONエンコードは行われていない。

{
  "categories": [
    {
      "categoryId": "im_copilot_usage",
      "parentId": null,
      "categoryName": "IM-Copilot 利用ガイド",
      "sortNumber": 1000,
      "localizes": {}
    }
  ],
  "assistantInfos": [
    {
      "assistantId": "sample-rag-assistant",
      "assistantKey": "im_logic_flow_assistant",
      "categoryId": "im_copilot_usage",
      "assistantName": "サンプルRAGアシスタント",
      "description": "",
      "parameters": { "flowId": "sample-rag-assistant" },
      "localizes": {}
    }
  ]
}
項目説明
categoriesアシスタントを分類するカテゴリの配列。categoryId・parentId・categoryName・sortNumber・localizesを持つ。フロー定義編のflowCategoriesと異なりparentIdを持つため、親子ツリー構造をサポートすると見られる（ユーザ定義編のuserCategoriesで未確認だったparentIdサポートの有無について、少なくとも本カテゴリ形式では存在することが分かる）
assistantInfosアシスタント本体の配列。各要素は文字列化されていない（flowDefinitionsやuserDefinitionsのような二重エンコードはない）
assistantInfos[].assistantIdアシスタントの一意なID
assistantInfos[].assistantKeyアシスタントの種別を表す固定文字列。確認できた値はim_logic_flow_assistant（LogicDesignerのフローを処理の実体として使うアシスタント）のみ。他の種別が存在するかは未確認
assistantInfos[].categoryIdcategories内のcategoryIdを参照
assistantInfos[].assistantName / description表示名・説明
assistantInfos[].parameters.flowIdこのアシスタントの処理を実行するフローのflowId（フロー定義編6章参照）。assistantKey: "im_logic_flow_assistant"の場合に使われるパラメータと見られる
assistantInfos[].localizes多言語対応の名称・説明

4. スケジュール実行トリガ（IM-JobScheduler連携）

フロー定義編17章で、フロー起動条件・トリガに関する記述がflow_definition.json内に見当たらないことを述べた。本サンプルから、少なくとも「スケジュール実行」によるトリガについては、LogicDesignerとは別製品のIM-JobSchedulerが担っていることが確認できた。job-scheduler.xml（XML形式、flow_definition.json等とは異なりJSONではない）でジョブ・ジョブネットを定義し、その中でフローを呼び出す。

<?xml version="1.0" encoding="UTF-8"?>
<root xmlns="http://www.intra-mart.jp/job-scheduler/data">
    <im-job-scheduler-data>
        <job-category id="im_copilot_usage">
            <localize locale="ja"><name>IM-Copilot 利用ガイド</name></localize>
            <!-- 他ロケールのlocalizeも同様に列挙 -->
        </job-category>
    </im-job-scheduler-data>
    <im-job-scheduler-data>
        <job-detail id="im_copilot_usage.sample_rag_assistant_vectorstore_build_job">
            <category-id>im_copilot_usage</category-id>
            <job-type>JAVA</job-type>
            <job-path>jp.co.intra_mart.foundation.logic.job.LogicFlowExecutorJob</job-path>
            <parameter key="flow_id">sample-rag-assistant-vector-build</parameter>
            <localize locale="ja"><name>ベクトル情報ビルドジョブ</name><description></description></localize>
        </job-detail>
    </im-job-scheduler-data>
    <im-job-scheduler-data>
        <jobnet-category id="im_copilot_usage">
            <localize locale="ja"><name>IM-Copilot 利用ガイド</name></localize>
        </jobnet-category>
    </im-job-scheduler-data>
    <im-job-scheduler-data>
        <jobnet id="im_copilot_usage.sample_rag_assistant_vectorstore_build">
            <category-id>im_copilot_usage</category-id>
            <localize locale="ja"><name>ベクトル情報ビルド</name><description></description></localize>
            <disallowConcurrent>true</disallowConcurrent>
            <serialize>
                <job-id>im_copilot_usage.sample_rag_assistant_vectorstore_build_job</job-id>
            </serialize>
        </jobnet>
    </im-job-scheduler-data>
</root>
要素説明
job-category / jobnet-categoryジョブ・ジョブネットを分類するカテゴリ。idとロケールごとの<localize><name>を持つ
job-detail個別のジョブ定義。idは<カテゴリID>.<ジョブ名>形式の命名規則と見られる
job-detail/job-typeジョブの種類。フロー実行の場合はJAVA
job-detail/job-path実行するJavaクラス。フローを実行するジョブではjp.co.intra_mart.foundation.logic.job.LogicFlowExecutorJob固定と見られる
job-detail/parameter[@key="flow_id"]実行対象フローのflowId（フロー定義編6章参照）
jobnetスケジュール実行の単位。1つ以上のjob-detailをserialize内のjob-idで順に指定する
jobnet/disallowConcurrent同一ジョブネットの多重実行を禁止するか

このXML自体には、実行スケジュール（cron式や実行間隔）に相当する項目が含まれていない。スケジュールは、IM-JobScheduler側の別の設定（ジョブネットに対するスケジュール登録）で管理されており、このXMLはあくまで「どのジョブ・ジョブネットが存在するか」の定義であると考えられる。

5. 未検証事項

  • assistant_definition.json・job-scheduler.xmlを含むリソース一式が、製品の標準エクスポート機能によって生成されたものか、ガイド用に手動で用意されたものかは未確認。
  • assistantInfos[].assistantKeyにim_logic_flow_assistant以外の値が存在するか。
  • IM-JobScheduler側で、実行スケジュール（cron式・実行間隔等）がどのファイル・データ形式で管理されているか。
  • im_chatのoptionで指定可能なmodelの値の全量（サンプルではgpt-4o-miniを使用）。
  • im_splitTextのchunkingMethodTypeに指定できる値の全量（サンプルではRECURSIVE_CHUNKINGのみ確認）。
  • IM-Copilot関連要素（本章2節）が、フロー定義編10.3節の標準要素一覧とあわせて何種類存在するか（公式ドキュメントの「IM-Copilot」カテゴリを参照すれば追加で判明する可能性がある）。
